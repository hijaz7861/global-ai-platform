# Delivery Roadmap

1. **Foundation — in draft:** FastAPI API, health contract, CI, database migration workflow, linting.
2. **Identity and initial tenancy — initial slice implemented, hardening remains:** users, password hashing, short-lived bearer access tokens, rotating hashed refresh tokens with replay detection and family revocation, persistent login/password-reset request rate limits, organizations, owner/admin membership management, expiring email-bound invitations, single-use invitation acceptance, tenant-scoped access.
3. **Catalog MVP — initial slice implemented:** listings, draft/active publication, public search and currency/price filters, bounded pagination, minor-unit pricing.
4. **Order/inventory MVP — initial slice implemented:** single- and multi-item orders (up to 50 unique listings), conditional stock reservation, per-buyer idempotency, buyer-scoped reads, unpaid-order cancellation, stock release, owner/admin inventory adjustments with append-only before/after history and audit events, seller-scoped order summaries, and platform-admin-triggered idempotent expiry with stock release.
5. **Accounting ledger — initial slice implemented:** tenant-scoped chart of accounts, balanced journal posting, immutable one-time counter-entry reversals, derived trial balance, currency/account checks, idempotency, and audit events.
6. **Accounting period controls — initial slice implemented:** organization-scoped non-overlapping periods, owner/admin listing and creation, audited one-way closure, and guards against new journal postings/reversals outside an open period once periods are configured, including PostgreSQL/SQLite insert triggers and tenant-row lock serialization with period closure. Period-specific trial balance, cursor-paginated account ledger, date-filtered income statement, and derived balance sheet grouped by currency are implemented; PostgreSQL/SQLite triggers reject overlapping periods, while cash-flow statements, reconciliation workflows, and broader posting/closure concurrency coverage remain open.
7. **AI provider layer — initial implementation:** optional allowlisted provider registry plus native Anthropic Messages and Gemini adapters; fixed provider origins, bounded requests/responses, timeouts, redacted errors, prompt-size cap, mocked tests, and opt-in configuration. Automatic capability-aware routing, cost/token accounting, monetary budgets, tool permissions, and agent workflows remain future work.
8. **Commerce hardening — partial:** multi-item carts and an idempotent expiry sweep are implemented and CI-verified. External scheduler provisioning, broader database concurrency/load tests, and full inventory/order race-condition coverage remain open. PostgreSQL CI verifies concurrent stock reservation, cancellation, and cancellation-versus-expiry.
9. **Financial hardening — next:** bank/payment reconciliation, cash-flow reporting, approval thresholds, accounting-domain review, and a payment sandbox; period-specific trial balance, account ledger, income statement and balance sheet are already implemented.
10. **Supplier operations — initial slice implemented:** organization-owned supplier profile, submission, platform-admin review, rejection reason and resubmission. Initial procurement requests, approved-supplier quotes, single-winner award and closure, idempotent purchase-order issue, buyer cancellation, and supplier fulfilment are implemented and CI-verified; procurement approval thresholds and fulfilment integrations remain next.
11. **Logistics and fulfilment:** shipping quotes, tracking, returns and disputes.
12. **Universal AI Connector Hub — partially implemented:** outbound provider registry and native Anthropic/Gemini adapters exist. The broader architecture is specified in [Hub architecture](UNIVERSAL_AI_CONNECTOR_HUB.md). Inbound MCP, encrypted secret-manager integration, capability routing, tenant budgets, tool allowlists, and approval gates remain incomplete.
13. **Security and autonomy controls — initial components implemented:** fail-closed release gate, signed artifact-bound evidence, durable single-host SQLite nonce store, and constrained Docker sandbox runner. The Security Gateway is specified in [SECURITY_GATEWAY.md], but not implemented as runtime middleware. Actual Docker execution on a rootless host, trusted key management, RBAC/signed approvals, persistent audit integration, monitoring, staged promotion, and rollback remain open. OAuth state/PKCE, secret management, webhook verification and revocation remain future work.
14. **Expansion modules:** rentals, real estate, workforce, education and business operations.
15. **Privacy and data lifecycle — initial export slice implemented:** authenticated profile/membership/buyer-order export excludes credentials and other users' records, with allowlisted audit counts; export coverage, consent, retention, and safe deletion/anonymization remain open. Four focused export tests are included in the successful CI run.
16. **Readiness:** threat model, full integration/regression tests, observability, backup restore, staging review.

Identity hardening now includes encrypted TOTP MFA, hash-only single-use recovery codes, refresh-token rotation, atomic code consumption, recovery-code-based MFA disable, persistent account lockout, previous-key verification during signing-key rotation, and invitation lifecycle controls, with CI coverage. A PostgreSQL 16 CI job runs migrations and concurrent refresh-token replay tests; broader database workload coverage remains open; trusted-proxy-only X-Forwarded-For parsing is implemented and tested. Atomic subject-lock rate limiting and an admin-triggered expired-record cleanup endpoint are implemented. Every phase needs acceptance criteria and automated tests.
